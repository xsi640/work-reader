# Work Reader

**一个长得像 ChatGPT 的本地小说阅读器**

左侧是会话式书库，右侧以 ChatGPT 消息流逐章展开正文。  
输入框既是阅读指令，也是全文搜索框。所有数据留在浏览器里，没有账号，也没有服务端。

## 功能

**阅读**

- 章节以助手消息的形态流式展开，用户指令以气泡出现在右侧。
- 打开书后自动回到上次读到的章节；“继续阅读”“随机读一章”都在首页。
- 章节底部直接翻页，也可以输入 `目录`、`第 5 章`、`下一章`。
- 书签、章节进度、复制本章、浏览器朗读（SpeechSynthesis）。

**书库**

- 拖拽 TXT 到窗口，或点击 `+` / “导入 TXT”。
- 自动识别章节标题；没有标题的文本会按长度自动切分。
- 书库支持继续阅读、重命名、删除、恢复示例书籍。

**界面**

- ChatGPT 式的 260px 侧边栏、768px 阅读栏、28px 圆角输入框。
- 会话按“今天 / 昨天 / 过去 7 天 / 更早”分组。
- 浅色 / 深色 / 跟随系统；字号、行距、衬线字体、页宽均可调。
- 桌面端可折叠侧边栏，移动端自动切换为抽屉。

**数据**

- 书库存在 IndexedDB，进度和书签存在 localStorage。
- 刷新或重开浏览器后继续阅读；可删除单本或清空全部数据。

## 快速开始

要求 Node.js 20.19+ 或 22.12+。

```bash
git clone git@github.com:xsi640/work-reader.git
cd work-reader
npm install
npm run dev
```

打开 <http://127.0.0.1:5173>。首次启动会写入三本原创示例小说；如果浏览器里有旧版数据，会自动迁移到新的“元数据 + 逐章”存储。

生产构建：

```bash
npm run build     # 产物在 dist/
npm run preview   # 本地预览构建结果
```

## 使用

1. 从左侧选择一本书，或把 TXT 拖进窗口。
2. 在底部输入框里发指令，或直接输入一句话在书中搜索。
3. 用章节底部的“上一章 / 目录 / 下一章”控制阅读位置。
4. 点击右上角 `Aa` 调整字号、行距、字体、页宽和主题。

### 输入框指令

| 输入 | 行为 |
| --- | --- |
| `下一章` / `继续` | 读下一章 |
| `上一章` | 读上一章 |
| `第 3 章` / `第三章` / `3` | 跳到指定章 |
| `目录` | 在消息流中展开章节目录 |
| `书签` | 为当前章添加 / 移除书签 |
| `从头开始` | 回到第一章 |
| `搜索 灯塔` / `搜索：灯塔` | 全文搜索 |
| 直接输入一句话 | 在全书正文中搜索 |

尚未打开书时，直接输入书名（支持 `《书名》`）即可打开。

### 快捷键

| 快捷键 | 行为 |
| --- | --- |
| `⌘K` / `Ctrl K` | 搜索书库与正文 |
| `Alt` + `←` / `→` | 上一章 / 下一章 |
| `Enter` | 发送 |
| `Shift` + `Enter` | 换行 |
| `Esc` | 关闭弹层 / 菜单 |

## 导入 TXT

优先按行首标题分章，例如：

```text
第一章 潮汐时刻
第二章 灯塔下的信
```

同时支持 `第1章`、`第三回`、`序章`、`楔子`、`尾声`、`Chapter 1` 等写法。  
标题之前少于 80 字的书名 / 作者信息不会单独成章；如果整本书没有可识别的标题，会按约 2400 字自动切分。书名默认取文件名。

## 大文件怎么处理

导入不是“把整个 TXT 读进内存”，而是一条流式管线：

1. `File.stream()` 按块读取，`TextDecoder` 增量解码；检测到乱码时自动回退 GBK。
2. 按行识别章节，逐章写入 IndexedDB；每 8 章合并一次事务，避免几千次小事务。
3. 书库只加载元数据（书名、章节数、章节标题、字数），不加载正文。
4. 打开书时只读当前章；消息流最多保留最近 8 章正文，旧章节仍然在本地数据库里。
5. 单章超过 60,000 字会自动拆成「（续 2）」「（续 3）」；没有标题的文件每 8,000 字自动分章。单条消息不会无限长。
6. 全文搜索逐章扫描、命中 40 条即停，可被下一次搜索中断。
7. 导入过程显示字节进度与已识别章节数，可以随时取消；取消或失败会删除已经写入的半成品章节。
8. 单个文件硬上限 200 MB，超过会直接提示拆分，不会启动导入；没有 `File.stream()` 的浏览器最多 20 MB。

本机 Chrome 实测（数据随设备变化）：

| 文件 | 结果 |
| --- | --- |
| 63 MB / 3,000 章 | 导入约 0.8 秒，搜索末章标记约 0.9 秒，JS 堆稳定在 20 MB 量级 |
| 23 MB / 无标题 | 约 1.5 秒自动切成 1,000 章 |
| 138 MB | 导入到 60%（82 MB / 3,528 章）时取消，数据库回滚到原有的 14 条章节记录 |

目录也不会一次渲染几千行：目录弹窗每页 200 章并支持关键词筛选；内联 `目录` 在超过 200 章时只显示当前章节附近，完整目录请用弹窗。

## 数据与隐私

- 书籍元数据：IndexedDB `work-reader` / `books`（书名、作者、章节数、章节标题、字数）
- 章节正文：IndexedDB `work-reader` / `chapters`，主键为 `[bookId, index]`
- 显示设置：`work-reader:settings`
- 阅读进度：`work-reader:progress`
- 书签：`work-reader:bookmarks`
- 上次打开的书：`work-reader:last`

旧版（v1）把整本书存在一条记录里；首次打开新版时会自动迁移成“元数据 + 逐章记录”，阅读进度与书签不受影响。

页面不加载外部字体、统计脚本或第三方接口。导入的 TXT 只在本机解析，不会上传。清除浏览器站点数据会同时清除书库，请自行保留原始 TXT。

## 浏览器支持

建议使用较新的 Chrome、Edge、Safari 或 Firefox。需要 IndexedDB；朗读功能依赖系统自带的中文语音，不同平台音色会有差异。

## 已知限制

- 目前只支持 `.txt`，EPUB / PDF 尚未实现。
- 没有云端同步，换浏览器或清除站点数据后需要重新导入。
- 单个 TXT 上限 200 MB；更大的文件请先按卷拆分。没有 `File.stream()` 的旧浏览器最多 20 MB。
- 全文搜索按章扫描；几万章的书第一次搜索可能需要几秒，但界面不会卡死，且可被新搜索中断。
- 目录弹窗每页 200 章；内联 `目录` 只显示当前章节附近，避免把几千行 DOM 塞进消息流。
- 对话指令是本地规则匹配，不调用大模型，不会产生 API 费用。
